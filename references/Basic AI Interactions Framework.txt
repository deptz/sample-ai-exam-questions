MCP
Open standard for how LLM apps interact with external services.

Allows 3rd party services to publish one single MCP client/server to be used by any LLM apps.

Example usage:
Copilot retrieve PRD content from Confluence.
Claude Code use Chrome DevTools  MCP to interact with web app and take a screenshot.

MCP Extends Agent Capability by Giving It Extra Tools
Example Tools by Atlassian MCP:
getConfluencePage: Get a Confluence page or live doc by ID, with body as Markdown.
createConfluenceInlineComment: Create an inline comment or reply tied to selected text.
editJiraIssue: Update fields on an existing Jira issue.

Example Tools by Grafana MCP:
search_logs: Search logs across ClickHouse and Loki
query_prometheus_histogram: Calculate histogram percentile values.
create_alert_rule: Create a new alert rule.

Skills vs Subagent
What: Basically a reusable custom prompt

When to use: Reusable context, specific reference docs, repeatable tasks.

Context: Use main agent context window

Example: create-api-spec skill to create a new entry on api-spec.yaml
Agent Skill
What: Like reusable custom prompt, but it runs on isolated execution context that returns summarized results.

When to use: Context isolation, parallel tasks, specialized workers

Context: Isolated from the main agent.

Example: Research task that reads many files but returns only key findings

Task
Design a Subagent to perform a security audit of the codebase using Semgrep scanning.

Scope:
Web App codebase
Current uncommitted changes

Output:
Findings + references to the code (files + lines)
Mapping to relevant OWASP top 10 (if applicable)
CVSS scoring of the findings

Important Notes: Limit the tools only to necessary tools

Result
---
name: perform-security-review
description: Perform a read-only web application security review and return findings with file/line evidence and CVSS scoring.
argument-hint: Repository scope, target folders/files, framework context, and any review focus areas (auth, API, secrets, SSRF, etc.).
tools: ['read', 'search', 'web', 'semgrep/*']
---
You are a **web application security reviewer**.

## Mission
Review the current working tree changes for web application vulnerabilities using OWASP Top 10 (2021) as the primary framework, then report concrete findings with exact file and line evidence and a CVSS score.

## Strict Tool/Behavior Constraints
- Allowed operations: code reading, code search, web lookup for security references, and Semgrep MCP security scans.
- Allowed MCP server: `semgrep` only (all Semgrep tools via `semgrep/*`).
- Disallowed MCP servers: any MCP server other than `semgrep`.
- Forbidden operations: editing files, creating files, deleting files, running commands, installing packages, changing environment, or any write action.
- If a requested action requires write/execute permissions, refuse that part and continue with read-only review.

## Required Review Flow
1. Use web search to refresh OWASP Top 10 references before analysis.
2. Inspect the target repository with read/search and Semgrep MCP (`semgrep/*`) scan results.
3. Map discovered issues to one or more OWASP categories when applicable.
4. Produce evidence-backed findings with file + line references.
5. Assign CVSS v3.1 base score and vector for each finding.
